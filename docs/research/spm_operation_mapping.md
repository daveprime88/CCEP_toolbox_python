# CCEP SPM12 operation audit and Python mapping

Audited 2026-09-09 against MATLAB commit `a25ed5d75536e5d3a8c2570c48f3196055a7f4bd` and the Python imaging implementation at the start of this study (`88b20f2575e54a6c7b0e95f91bd5864c04f4a619`). This is a source audit and implementation recommendation, not evidence of numerical or clinical equivalence. Later implementation commits may resolve the findings below.

MATLAB paths below are relative to `CCEP Toolbox/MRI and CT Coregistration routine/`. `P/` means `Preprocess/`; `C/` means `CoOrdGrabGui/`. These are the actual checked-in call sites, including parameter values that differ from SPM defaults. Runtime SPM version, templates, batch outputs and original patient reference data still need capture on the reference computer.

## Recommended boundary

Use ANTsPy for registration, deformation application, N4 and prior-informed segmentation; use NiBabel and small typed NumPy modules for file geometry, contact shapes, native tissue sampling and atlas lookup. Keep transforms as explicit ordered, checksummed artifacts with source and destination spaces. Treat the ANTs segmentation/normalisation pipeline as an approved algorithm replacement assessed by scientific outcomes. Preserve the CCEP-specific calculations and document their legacy quirks separately.

SPM's unified segmentation estimates tissue and normalisation together; separate N4, registration and Atropos calls do not reproduce that joint model. The current Python `segment()` requires priors already on the native image grid. It does not yet perform the template-to-subject prior propagation that makes a complete replacement workflow possible. SPM itself describes using unified segmentation to estimate normalisation, then applying its deformation to other images registered to the subject T1. [SPM workflow documentation](https://www.fil.ion.ucl.ac.uk/spm/docs/tutorials/multi/fmri/)

## Transform conventions that must be explicit

For `registration(fixed=template, moving=subject)`, the following are different operations:

| Task | ANTs transform list | Affine inversion |
| --- | --- | --- |
| Subject image → template grid | `fwdtransforms` | False for all forward steps |
| Template image/priors → subject grid | `invtransforms` | True for affine steps, false for inverse displacement fields |
| Template points → subject points | `fwdtransforms` | Same forward steps |
| Subject points → template points | `invtransforms` | True for affine steps, false for inverse displacement fields |

Image resampling evaluates source coordinates for target voxel centres. This explains the apparent reversal for point application. Preserve ANTs' returned transform ordering; never sort paths or infer order from filenames. ANTs' official examples also show composing an inverse affine with the inverse warp for reverse image mapping. [ANTs transform guide](https://github.com/ANTsX/ANTs/wiki/Forward-and-inverse-warps-for-warping-images%2C-pointsets-and-Jacobians)

Current `Registration` stores path tuples without inversion flags. A rigid/affine-only result uses the same `.mat` file in forward and inverse lists. ANTsPy's default inversion heuristic does **not** invert a one-element affine list: it special-cases a two-element matrix-then-warp list. Consequently, feeding `inverse_transforms` directly into a future reverse-mapping operation can silently go in the wrong direction. Store `TransformStep(path, invert)` and a declared image-space mapping in a versioned manifest. Validate lengths and reject inversion of displacement fields. The public point boundary must convert RAS→LPS before ANTs and LPS→RAS after. [ANTsPy apply-transforms source](https://antspy.readthedocs.io/en/latest/_modules/ants/registration/apply_transforms.html)

The same ANTs source says output pixel type follows `fixed`. Preserve a floating-point reference for continuous values, especially the warped contact sphere. This is a **robustness requirement, not a demonstrated bug in the current file-based implementation**: installed ANTsPy 0.6.3 has `image_read(..., pixeltype='float')`, so the existing direct reads already convert integer files to float. An explicit float boundary protects future callers passing in-memory integer images or `pixeltype=None`. Verify fractional sphere values using an integer file and an explicitly integer in-memory reference. [ANTsPy image-reading source](https://antspy.readthedocs.io/en/latest/_modules/ants/core/ants_image_io.html)

For public NumPy geometry, index `(0,0,0)` denotes the first voxel centre; NiBabel affines map those indices to RAS+ world coordinates. An SPM `V.mat` captured from MATLAB uses one-based voxel indices. Convert a captured SPM matrix with `A_zero = A_spm @ translate(1,1,1)` before applying zero-based Python indices; do not add one when reading the NIfTI directly through NiBabel. RAS↔LPS changes world signs, not array storage order. [NiBabel coordinates](https://nipy.org/nibabel/coordinate_systems.html)

SPM `y_` fields are not interchangeable with ANTs displacement files. Keep the existing absolute-RAS pull-field adapter separate, record field/reference/native roles and dimensions explicitly, and validate a captured field before inferring a mapping from its filename. Its current linear/nearest resampling also does not implement SPM's degree-4 interpolation option.

### Modulation: exact SPM discretisation and a Python density contract

The official SPM12 writer provides a more precise definition than “multiply a warped probability by a Jacobian.” `spm_preproc_write8.m` (revision 7415) forms the native-to-template voxel mapping including `res.Affine` (`:173–214`), pushes tissue values into the output grid (`:397–405`), then writes `mwc` after multiplying by `abs(det(M0)/det(M1))`, the native/output voxel-volume ratio (`:410–420`). Forward `y_` output instead inverts this mapping and stores native world coordinates on the target grid (`:450–459`). The normalized tissue grid is set separately from CCEP's later 1 mm MRI write. [SPM12 tissue writer](https://github.com/spm/spm12/blob/main/spm_preproc_write8.m)

The push kernel distributes each finite native value to eight target neighbours with trilinear weights; it accumulates mass rather than interpolating an average. Out-of-domain mapped points are omitted in the ordinary `push` variant. Therefore exact discrete SPM `mwc` parity requires this push convention and its bounds, even if a pull-Jacobian formulation has equivalent continuous meaning. [SPM push kernel](https://github.com/spm/spm12/blob/main/src/shoot_diffeo3d.c)

For an explicitly named **ANTs outcome-equivalent density** operation, let `P(x)` be native tissue fraction and `T(y)` the complete target-to-native physical pull map. Define:

```text
unmodulated(y) = P(T(y))
full_density(y) = P(T(y)) × abs(det(DT(y)))
tissue_volume_mm3 ≈ sum(full_density) × target_voxel_volume_mm3
```

This is the change-of-variables formula; it is a proposed Python contract, not a claim of identical SPM discretisation. With millimetre physical Jacobians, do not multiply by an additional voxel-volume ratio inside this pull formula: voxel volume belongs in the final integration. Record `quantity="tissue_density"`, `modulation="full_transform"`, `mapping="target-to-native pull"`, template/native identities, target geometry and interpolation. Keep these outputs distinct from bounded posterior probabilities and from a deliberately chosen `nonlinear_only` modulation option.

An ANTs `1Warp.nii.gz` is only the nonlinear component when the affine remains in a separate `.mat`; its Jacobian omits affine volume scaling. For full modulation, evaluate the complete composed pull field on the output grid before computing its physical Jacobian. Alternatively, prove the affine/nonlinear chain rule with an explicit composition order and evaluate each derivative at the appropriate intermediate position. Do not treat the determinant of the stored forward image affine as a native-to-template point determinant without checking direction.

ANTs' Jacobian tool reads a displacement image, rather than accepting an affine-plus-warp list. Its geometric branch and derivative branch are separate; the derivative branch clips negative determinants to zero, and the log output floors at `.001`. Thus a log-Jacobian alone is unsuitable for proving absence of folds. Use explicit signed determinant diagnostics for QA, record the algorithm, and do not hide nonpositive values by taking absolute values without first detecting them. [ANTs Jacobian source](https://github.com/ANTsX/ANTs/blob/master/Examples/CreateJacobianDeterminantImage.cxx)

Local analytic probe with ANTsPy 0.6.3: physical pull displacement `u(y)=(s-1)y`, a 17³ grid with origin `(-8,-8,-8)` mm, and a three-voxel interior margin gave exactly `0.125` for `s=.5` and `8.0` for `s=2`, with both geometric and derivative modes. These fixtures establish pull direction: expansion of the output support by 2 requires density divided by 8. Add a compact-support tissue phantom to verify integrated mass, translation/rotation determinant 1, anisotropic scale product, nonzero affine centre, oblique spacing, explicit affine-only composition and clipped-FOV mass loss. Compare an SPM push fixture separately; the two numerical schemes need not have identical boundary or aliasing behavior.

## CCEP/MarsBaR quirks to capture before correction

1. **Cylinder argument mismatch.** `CCEPTissueProbCalc.m:122–125,174` builds radii 2 and 4 cylinders and passes `Shape`. `TissueProbCylinderCreate.m:23–46` recognises only `Cyl|New` for that argument, so it ignores the supplied shape and generates the default radius-2 cylinder. `CylinderCreation.m:24–41` produces three rings, each with 12 points when `NumPoints=11`, including the duplicated seam. The actual default point count is 36, not 72 or 33.
2. **Cube centring.** `CCEPTissueProbCalc.m:137–149` multiplies binary vertices by radius 2, then by 2 and subtracts 1: coordinates become -1 and 3, with centre point 1. The resulting cube is shifted relative to the contact, not centred at zero. Rectangle scales X by 1.5.
3. **“Sphere” cloud.** `CCEPTissueProbCalc.m:160–161` samples a uniform cube bounded inside radius 2, not a uniform solid sphere. Capture actual random points, not only a seed across MATLAB/NumPy RNGs.
4. **Rotation convention.** `RotationalAffine.m:39–58` computes `Rx*Ry*Rz` and multiplies row points on the right. A conventional column-vector SciPy rotation used without transposition/reordering changes the result. Angles above `2*pi` trigger conversion of all angles from degrees.
5. **Tangent is not generally orthogonal.** `VectorTangentNorm.m:24–35` normalizes elementwise reciprocal of normal, replaces infinities by 1, then takes a cross product. A corrected orthonormal frame belongs in a separate delta after baseline capture.
6. **MarsBaR sphere rasterisation.** Bundled `marsbar-0.44/@maroi_sphere/voxpts.m:15–24` uses row norms of the affine linear part, finds axis bounds around the inverse-affine centre, then measures scaled index differences. Current `geometry.sphere()` instead evaluates Euclidean world distances. These agree on suitable axis-aligned grids but are not generally equivalent on anisotropic oblique/sheared grids. Provide a named compatibility rasteriser if the corpus exposes this difference; do not broaden claims from the current identity fixture.
7. **GUI-mediated numeric precision.** Tissue samples pass through SPM intensity display text and single precision before mean; positions go through `num2str`. Exact capture needs these intermediates, not only raw image arrays.
8. **Input and failure quirks.** Missing-tissue check repeats GM rather than checking CSF (`CCEPTissueProbCalc.m:83`); custom atlas path leaves `BBox` undefined (`:98–105,207`). These are recorded historical failures; a Python validation improvement can be explicit without pretending the original accepted those inputs.

## Next commits and tests

1. **Transform artifacts and geometry boundary.** Add explicit step inversion, reference-space identity, input/output hashes, geometry checks and reusable image/point apply functions. Test asymmetric affine translation plus rotation about a nonzero centre, reverse round-trip, nonlinear composition, landmark/image-impulse agreement and RAS/LPS signs. Affine-only inverse testing is mandatory; identity alone misses the bug.
2. **Explicit registration presets.** Separate CT-to-T1 rigid from T1-to-template nonlinear use cases. Persist all effective parameters, including initialization, masks, sampling, smoothing units, iterations, precision, threads and library version. Current ANTs defaults include center-of-mass initialization, multiresolution schedules and single precision; changing installed ANTs can otherwise change the workflow unnoticed. [ANTsPy registration source](https://antspy.readthedocs.io/en/stable/_modules/ants/registration/registration.html)
3. **Template prior propagation.** Apply the inverse image mapping to six ordered template priors on the native T1 grid. Check finite bounded values, supported voxels, class sum and mask consistency. Make any normalization of interpolated priors an explicit recorded policy. Keep the exact named template/TPM atlas provenance; “MNI” alone does not identify a template.
4. **Native tissue and atlas workflows.** Port compatibility sampling shapes and table lookup independently from ANTs segmentation. Use tiny analytic volumes with known per-voxel tissue/labels, axis-aligned and oblique affines, off-centre contacts, boundary ties, missing labels, OUT and duplicate sample points. Use fixture arrays for random cloud parity.
5. **Normalised MRI/tissues and contact ROIs.** Construct and verify the requested 1 mm target grid; test first/last voxel centre against requested bounds. Keep unmodulated probabilities, modulated tissue density and contact masks distinct. Test `.99/.95` fallback, empty sphere, partial-FOV clipping, integer target dtype and nonlinear centroid-versus-point differences.
6. **Reference comparison study.** For each deidentified matched T1/CT case save original and reoriented headers, masks, SPM batch/config/version, native tissue volumes, deformation fields, all shape sample coordinates, contact centroids and atlas outputs. Compare candidate pipelines on independent landmark error in millimetres, native tissue overlap/calibration, contact tissue distributions, atlas agreement, Jacobian/folding diagnostics and runtime. Thresholds must be set before inspecting holdout results; pending data are not evidence that an implementation is wrong or equivalent.

The Python-only synthetic tests establish transform mechanics and software contracts. They cannot by themselves establish SPM outcome equivalence, robustness to CT metal artifacts, or accuracy on the eventual scientific corpus.
